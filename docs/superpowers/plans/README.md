各フェーズは単体で「動く・テストが通る」状態に到達する。

## 進め方の原則

- **TDD**: 失敗するテストを書く → 失敗を確認する → 通す最小実装 → リファクタ
- **ミューテーションテスト**: `packages/geo` / `packages/core` はスコア 85% を下回ったら失敗扱い
- **1 タスク = 1 コミット**: タスク末尾で必ずコミットする
- **回帰**: タスク完了の条件は「そのタスクのテスト」ではなく「`npm test` 全件が緑」

#### そこに至るまで（数字を 3 回捨てた記録）

Stryker は **Timeout を Killed と同じ「殺せた」に数える**。
Timeout はテストが変異を検知した結果とは限らないので、報告値は常に**上振れの方向**に嘘をつく。

| 回  |     報告値 | Timeout | 判定                                                                              |
| --- | ---------: | ------: | --------------------------------------------------------------------------------- |
| 1   |     86.95% |   13 件 | Timeout を 1 件ずつ実ソースに当て直して検証 → 実スコアは **86.65%**               |
| 2   |     88.92% |  133 件 | **破棄**。実行中に Mac が 11 回・計 138 分スリープしていた                        |
| 3   | **87.25%** |    1 件 | `caffeinate -dims` 下で再計測。スリープ 0 回・Timeout は本物の無限ループ 1 件のみ |

1 回目は `reports/mutation/mutation.json` の Timeout 13 件について、記録された `location` と
`replacement` を実ソースへ当て直し、1 件ずつ全スイートを流して確かめた。
結果は「実際に殺せていた 11 件／**隠れていた生存 2 件**」で、報告済みの Survived 86 件と
合わせて実際の生存は 88 件、実スコアは `(560+11)/659 = 86.65%` だった。

隠れていた 2 件はどちらも `apps/api/src/middleware/role-guard.ts:54`（`requireOwnerActor` の
未認証判定）で、報告済み Survived のうち 2 件も同 43 行（`requireUserActor` の同じ判定）だった。
**原因は 1 つ**で、この 2 関数に「未認証のとき 401」のテストが無かったこと。
認証判定を消しても後段の `isUserActor` / `isOwnerActor` が匿名を弾いて 403 になるため、
呼び出し側から「ログインすれば通るのか、ロールが足りないのか」が区別できなくなるのに緑のままだった。
`requireAdminActor` には同じテストがあり、その変異は殺せていた。

401 を名指しで縛るテストを 2 件足した（17 → 19 件）。効果は再計測の差分と一致している:

|        | 1 回目（実測値ベース） | 3 回目 |     差 |
| ------ | ---------------------: | -----: | -----: |
| 殺せた |                    571 |    575 | **+4** |
| 生存   |                     88 |     84 | **−4** |

動いた 4 件は `role-guard.ts` の 43 行・54 行それぞれの条件式と本体（2 行 × 2 変異）で、
再計測後の生存リストから `role-guard.ts` は**消えている**。

2 回目を破棄した理由: スリープ中は全プロセスが凍るが Stryker のタイムアウトは実時間で判定するため、
復帰時に実行中の変異が concurrency ぶん（12 件）まとめて Timeout になる。
偽物だと断定できた決め手は、同じ変異が 1 回目に **Survived** だったこと
（テストが通って終わる変異が本質的にタイムアウトすることはない）。
`src/lib/logger.ts` は Survived 2 → Timeout 2、`src/lib/validate.ts` は Killed 7 → Timeout 7 と動いていた。

**計測時の注意は `stryker.base.mjs` に実測付きで集約してある。**
要点は 3 つで、いずれも「テストの強さと無関係な理由でプロセスが落ちると Killed に記録される」という
同じ穴から来ている: ①裏で `npx vitest run` を走らせない（ポート枯渇）、
②`pkill -f vitest` を打たない（子プロセスが巻き添え）、③macOS では `caffeinate` を噛ませる。

`npm run format:check` の対象は `**/*.{ts,tsx,js,json,md}` で、**`.jsonc` は入っていない**。
そのため `apps/api/wrangler.jsonc` は整形ゲートの外にあり、`npx prettier --check .` では警告が出る。
対象を広げると prettier が JSONC に末尾カンマを足すので、wrangler の受理可否を確かめてから判断すること
（未確認。Phase 10 の検討事項）。

Phase 3 で追加した検証のうち、他フェーズでも効き続けるものが 2 つある。

- **CHECK 制約の網羅メタテスト**（`apps/api/src/db/schema/check-constraints.test.ts`）:
  マイグレーション上の CHECK 制約 104 個が 1 つ残らずテストで名指しされていることを機械的に縛る。
  制約を足してテストを書き忘れると赤くなる（実測で確認済み）。
- **部分索引の DDL 検証**: 部分索引 3 本の `WHERE` 句を `sqlite_master` の DDL で直接見る。
  `EXPLAIN QUERY PLAN` の索引名だけでは `WHERE` が消えても検知できないため。

Phase 4 には、後続フェーズで効き続ける機械検査が 3 つ入る。

- **Actor ファクトリの閉じ込め**（4-3）: `brandActor` を呼んでよいファイルを許可リストで固定する。
  リストに無いファイルから Actor を捏造できないため、権限の迂回路が作れない。
- **リポジトリ規約の検査**（4-10）: TypeScript Compiler API で全リポジトリ関数の引数を走査し、
  `(db: Database, actor: Actor, ...)` の形になっていない関数を落とす。「Actor を受け取り忘れる」が起きない。
- **ルート表 ↔ 実装の突合**（4-14）: Hono に登録された実際のパス集合と、
  テスト側が宣言したパス一覧を `toEqual` で突き合わせる。ルートを足して権限テストを書き忘れると落ちる。

3 つとも「実装者の注意力」ではなく「型検査とテスト」に権限の正しさを委ねるための仕掛けで、
Phase 7〜9 で API を増やすたびに自動で効く。
